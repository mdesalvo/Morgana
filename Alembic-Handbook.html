Alembic Handbook 2

Architecture Overview

Alembic is Morgana's authoring workbench: an AI-conducted functional interview that distils a domain expert's own words into a complete Morgana domain — intents, agent prose, tool contracts, C# assets and non-regression scenarios — with no prompt ever written by hand. It is not a channel: it never calls a running Morgana, holds no JWT, joins no conversation pipeline — its only external dependency is an LLM. And it is not a filesystem tool: configuration arrives as an upload and leaves as a download, since at runtime Alembic can live anywhere — a cloud, an on-prem box beside Morgana, a laptop.

Alembic is itself an agent of Morgana: its own prompt is layered from an alembic.json of identical shape to a domain agent's (Target / Instructions / Personality / Formatting), composed with Morgana's own Personality resolved live from morgana.json — the same framework the domains it authors will run under.

🗺

The Interview

C# owns the facts, the model owns the conducting. A domain-mapping pass turns the client's own words into intents, then four passes per agent build its prose incrementally, each reading back only what is already settled.

✅

Deterministic Validation & Recap

Every rule the framework enforces later and more expensively is checked here first, for free. The recap is the real composed prompt — framework layer and domain layer — not a summary of what was said.

📦

Turnkey Emit

One archive: a ready .csproj/.slnx, generated X.g.cs sources split from a client-owned X.cs half, a working LLM-authored mock per toolkit, and an unconditional migration report.

🧪

Non-Regression from Day One

A starter PromptHarness suite is derived from behavioural templates for the domain just authored, plus a cross-agent coherence pass that catches overlapping intents before the client leaves.

Alembic Handbook 3

The Interview

A domain is a configuration of two halves — Intents and the Agents that answer them one each — so the interview opens on the half that comes first in every sense. Only then does it walk the map, four passes per entry, until every intent has its agent. Each pass is a fresh agent and a fresh session: what crosses the boundary is the configuration, read back as settled fact, never the conversation replayed.

PassRunsSettles
DomainMapperonceThe whole Intents section: every name, description, label and opening sentence
AgentModelerper entryThe agent's Target — what it does, what it must never do
AgentVoicerper entryThe agent's Personality — which facet of Morgana this agent is
ToolkitModelerper entryThe tools, their descriptions, parameters, scopes and sharing
AgentInstructorper entryInstructions — behavioural rules, written after the toolkit exists
AgentFormatterper entryFormatting — how the agent presents its own tools' output

Doctrine

  • One question, one step. Every question is a step, and half an answer advances it — the rest is inferred, proposed and corrected rather than asked twice. Asking three times ends the interview whether the client says so or not.
  • Closed questions only where the answer adds nothing. A quick-reply button never appears on a question about the client's domain — their words are the material being distilled. It appears only for the answer Alembic already knows the whole of: agreement, “nothing missing”, “nothing to avoid”.
  • The client never writes prose. They answer questions about their own work, in their own words; Alembic writes the configuration and says back what it understood — sparing a domain expert from having to become a prompt author.
  • Backwards is the client's, forwards is not. Going on is a claim a step is settled, decided by the state machine; going back is a claim something needs changing, and only the client can make that call.
The map is a choice, not an inventory. The DomainMapper pass is worded to elicit the subset of the client's own processes they are installing Morgana to run — not a description of their whole business. What they keep off the map never appears on it.

Configuration Reference

Alembic follows the same ASP.NET configuration hierarchy every unit in the repository does: appsettings.json → environment variables → User Secrets. It shares its UserSecretsId with Morgana.Web, so in-repo it runs against whatever LLM provider and tiers the working copy is already wired to — nothing to configure twice.

SettingDescription
Morgana:LLM:ProviderLLM backend: Anthropic, AzureOpenAI, Ollama, OpenAI
Morgana:LLM:{Provider}:Tiers:PerformanceThe only tier Alembic declares — it never uses the Efficiency die. MagicDust carries both axes at zero: pricing is never read, since Alembic calls GetChatClient(Performance) directly rather than going through the metered agent adapter
Alembic:Work:AutosaveSecondsHow often the Draft in the circuit is snapshotted as a fallback for “Save my work” — never a resumption path on its own, only a floor under that one button (default: 30)
No single-tier deployment: because Alembic declares only Performance, it does not run against a single-tier deployment (Ollama being the canonical case) until a Performance entry is configured — the same “no cross-tier fallback” rule the framework itself enforces.

The Regeneration Contract

Generated C# is split across two files per class — the non-destructive-regeneration mechanism, and the line between what is templated (deterministic, so a re-run produces no spurious diff) and what is authored by the LLM.

FileOwnerRule
X.g.csAlembicAttributes, constructor, partial signatures — always overwritten
X.csThe clientThe working mock body, then the client's real integration — written once, never touched again

Docker Deployment

Alembic's Docker service is profile-gated, so an ordinary compose up skips it — it is an authoring-time tool, not part of the always-on runtime footprint.

# Run Alembic standalone docker compose --env-file .env --env-file .env.versions --profile authoring up alembic # Or from source cd Alembic/Distiller dotnet run # https://localhost:5005, no running Morgana required

The Emit

The reviewed domain downloads as one archive, because the pieces are only correct together — an agents.json whose toolkit has moved on from the C# beside it is a startup failure waiting to happen.

  • A ready .csproj / .slnx, referencing Morgana.AI and Morgana.Contracts by PackageReference, pinned to the exact build Alembic itself runs against
  • The domain configuration, agents.json, embedded as a resource
  • Generated sources following the X.g.cs / X.cs split, one pair per agent and per toolkit
  • A working, LLM-authored mock per toolkit — not a stub — so the client can talk to their agent on the first run and hear whether the interview's prose is right
  • An unconditional migration report, diffing the domain against its own baseline — greenfield included, because a report that only appears when something is wrong is a report nobody has learned to read on the day it matters
  • README.md (carrying the two-halves convention), MIGRATION.md, and the interview's own save file
Alembic Handbook 7

Starter Non-Regression Scenarios

A domain agent is its prose, and prose gets edited — a client who leaves without scenarios has a domain nobody can revise safely. Alembic derives a starting PromptHarness suite from a library of behavioural templates, replacing every domain-word placeholder with this domain's own language.

TemplateProtects
capability-happy-pathThe flow the agent exists for, end to end
prerequisite-before-actionIt asks for what it needs instead of inventing it
confirmation-before-commitNothing irreversible happens before a yes
boundary-refusalThe edge its own Target commits it not to cross
tool-choice-under-ambiguityA request between two tools reaches the right one
absent-subjectIt says nothing was found instead of writing something plausible
withheld-detailWhat its Formatting keeps back stays back
established-context-not-reaskedA value given once is not asked for twice
Discretionary pass & coherence pass: after the templated base, one further call may add up to two scenarios of its own for a rule that holds only in this domain. A separate cross-agent coherence pass then reviews the whole domain at once — overlapping intents, contested capabilities, a value published under two names — the relational defects no per-agent interview pass could ever see. It advises, never blocks: a domain expert who disagrees about their own business is usually right.
Alembic tests itself, too: a dedicated Alembic/PromptHarness — distinct from the one shipped for Morgana — drives a scripted domain expert through a real interview and asserts on the mapping, the conduct across passes, and the finalization emit, so the workbench stays honest as it evolves.

Getting Started

Two doors, from the landing page: distil a brand-new domain, or continue one already in progress.

A Fresh Domain

  • 1. Begin. One question at a time, on an otherwise empty screen — the process itself is Alembic's alone to know.
  • 2. Map it. The DomainMapper pass turns what the client is installing Morgana to handle into a set of intents — a choice, never an exhaustive inventory.
  • 3. Build each agent. Target, Personality, Toolkit, Instructions, Formatting — one lap per entry on the map, until the last one is accepted.
  • 4. Review. Deterministic findings first, then the real composed prompt — exactly what the running agent's own model will read.
  • 5. Morganize. Validate, then download: one archive, ready to dotnet build and drop into a Morgana plugins/ folder.

Continuing One

Nothing about an interview is lost to a closed tab past the last autosave interval: Save my work hands over a file at any point, and the import page reads it back — by content, never by filename — to resume exactly where the client left off, mid-agent included.

The client never uses the agent. The people who will are their customers — so everything Alembic writes is addressed to the agent about those people, never to the client conducting the interview.
